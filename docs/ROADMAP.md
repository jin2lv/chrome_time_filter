# 时光机 — 未来路线图与场景验证

> 版本：2026-08-14
> 前提：v1.0 已完成雪球个股页虚拟分页和同花顺基础适配，现调整为“雪球全场景优先”的金融首发版本；其他平台须在雪球完整验收后串行推进。本文档涵盖 v1.0 后续、v1.1~v2.0 的场景验证、平台扩展与技术方案。

---

## 1. 需求验证框架

一个场景必须通过"三把刀"才值得投入：

| 刀 | 问题 |
|---|------|
| **刀1：损失不可逆？** | "看到不该看的内容"后，损失是否无法挽回？ |
| **刀2：平台自己解决了吗？** | 平台是否已有原生方案？ |
| **刀3：时间是正确的切割维度吗？** | 用户想切的是"时间"还是其实是语义？ |

---

## 2. V2 核心场景（通过三把刀验证）

### S1. 投资决策噪音（v1.0 已做）★★★★★
- 损失：真金白银
- 平台无解：雪球/股吧没有"只看昨日收盘前"的能力
- 结论：产品原点，最硬的需求

### S2a. 追剧/追番党（B站评论区、豆瓣、贴吧影视区）★★★★★
- 损失：剧透无法"没看见"
- 平台半解：豆瓣有"剧透"标签礼仪但靠自觉
- 时间维度：窗口模式是**近似解**（同一窗口内仍有看得快的人剧透看得慢的人），语义级才是完整解 → 见 §4 BYOK
- **B站适配范围 = 评论区 + 影视区讨论页**（动态流因深度硬限制放弃）

### S2b. 体育录像党（虎扑、懂球帝、直播吧）★★★★★ — **V2 版本**
- 损失：比追剧更刚。体育内容时效以小时计，醒来看到比分 = 整场比赛报废
- 平台无解：体育社区首页标题直接带比分
- 时间维度：开赛时间 = 绝对切割线，**无需语义判断**
- 平台结构老、适配难度低，低投入高回报

### S3. 增量续读（"从我上次看到的地方继续"）★★★★ — **V2 版本**
- 场景：贴吧直播贴/长楼、知乎长帖更新。上次读到 8 月 5 日，今天只看 8 月 5 日之后的新楼层
- 损失：高频——在几百层已读内容里反复翻找"我看到哪了"
- 平台半解：贴吧有倒序但没有"从书签位置继续"
- 时间维度：窗口模式的下半边。技术上只需加"记住上次时间下界"
- 存储设计：`lastRead.<domain>` → URL → timestamp，LRU 最多保留 50 条

### S4. 合订本/热点反转考古（知乎 + 贴吧）★★★☆ — **V2 版本**
- 场景：热点事件反转后"看反转前的回答"
- 损失：认知污染不可逆——看过反转结论后无法还原"当时人们真的怎么想"
- 平台无解：知乎按赞同排序，高赞已被反转后的舆论重排
- 挑战：知乎显示"编辑于"而非发帖时间，需 `strip_pattern` 前缀剥离 + UI 标注"可能使用编辑时间"
- 中频需求，排在 S1/S2/S3 之后

### S5. 公司近况背调（脉脉/看准网）★★★
- 场景：求职前"只要近三个月"的公司评价
- 注意方向反了：是"只要新的"——需 `direction: after` 反向过滤
- 平台限制：脉脉有登录墙，限制了可触达用户
- 中优先级，保留观察

## 3. 被验证"杀掉"的候选

| 候选平台 | 死于哪把刀 | 原因 |
|----------|-----------|------|
| **电商评价（京东/淘宝/大众点评）** | 刀2+刀3 | 平台自带时间排序；用户真实动作是"找差评"（语义维度），不是"按时间切" |
| **Hacker News** | 刀1 | 用户"找回某事件前讨论"的需求很弱，HN 价值在链接质量不在时效切割 |
| **Stack Overflow / GitHub Issues** | 刀2 | 自带时间排序，插件增量小。降为"如有富余顺手做" |
| **RSS 阅读器** | 刀2 | 自带未读状态和时间排序，需求已被解决 |
| **学术舆论考古** | 技术前提冲突 | 需快照能力，与"无后端、无快照"的非目标冲突 |
| **微博** | 深度硬限制 | 关注流仅约 10 页，核心场景无法成立 |
| **B站动态流** | 深度硬限制 | "实时信息流"，无历史检索 |
| **小红书 / 抖音网页版** | 登录墙+加密+虚拟列表 | 投入产出比最差，明确放弃 |

## 4. BYOK 大模型扩展（V2 核心差异化）

### 4.1 设计约束
**无后端、用户自配 API Key**（DeepSeek / OpenAI 兼容接口）、显式开启、内容外发需独立同意。

### 4.2 语义级剧透防护（核心用例）

时间窗口的固有缺陷：窗口内仍有超前剧透。**时间切不干净，只有语义能切干净。**

- 用户配置：「《XX》我追到第 3 集」
- LLM 判断每条帖子涉及的剧情进度，> 3 集的 → 模糊策略
- 是把剧透场景从"近似解"升级为"完整解"的差异化杀手锏

### 4.3 自然语言过滤规则

"隐藏所有转会传闻帖"、"隐藏晒收益的帖子"——本质是关键词过滤的语义升级版，与时间过滤叠加（先按时间切，再按语义筛）。

### 4.4 工程方案

```
Content Script 过滤管道：
  时间过滤（即时生效）→ 语义过滤（异步）
    ↓
  ① 收集可视区帖子文本 → 批量（10帖/次）→ fetch LLM API
    ↓
  ② 结果本地缓存（帖子 ID → 判定，LRU 1000 条，7 天过期）
    ↓
  ③ SPOILER/UNCERTAIN → 叠加模糊策略；SAFE → 保持时间过滤结果
```

### 4.5 成本控制

| 策略 | 实现 |
|------|------|
| 批量合并 | 10 帖/次调用 |
| 仅处理可视区 | IntersectionObserver |
| 本地缓存 | 7 天过期，重复帖不调用 |
| 边界模糊区 | 时间过滤已判定"明显安全"的帖跳过语义 |
| 模型选择 | 默认 DeepSeek-V3（便宜），支持本地 Ollama（零成本） |

### 4.6 隐私与合规

- API Key 存 `chrome.storage.local`，不上传任何服务器
- 独立开关（默认关）+ 首次开启明示"帖子内容将发送至你配置的 API 服务商"
- Content Script 直连用户配置的 baseURL，不经过自有服务器

## 6. 技术演进

### 6.1 雪球个股虚拟分页（v1.0 已实现）

```
从原始第 1 页串行扫描 → 时间过滤 + data-id 去重 → 收满 10 条
  → 渲染当前虚拟页并停止
  → 仅在用户点击虚拟“下一页”时从游标继续
```

- 平台 DOM 约束全部在 `xueqiu.json`：列表、稳定 ID、原帖链接、原生分页、页码输入和加载等待。
- 通用引擎缓存已收集帖子；上一页不重扫，下一页不预取超过当前页所需内容。
- 200 是一次会话的原生页硬上限而非目标；支持取消、末页、上限、重复页与加载超时状态。
- 虚拟列表使用展示克隆，保留原帖链接；原生交互控件不在克隆上承诺可用。
- 修改截止时间或关闭过滤会取消旧会话并恢复雪球原生列表和分页。
- 全部/讨论/投资者关系/交易/资讯/公告共享配置规则，但缓存与扫描会话按当前活动类别隔离；类别切换会重新绑定雪球替换后的列表和分页 DOM。
- 原生列表/分页由虚拟会话持续隐藏，抵抗雪球异步覆写 `display`；类别 DOM 稳定等待与逐页扫描轮询使用独立间隔，空类别不会复用旧类别 DOM。

### 6.2 雪球首页类别信息流（v1.0 实现与验收中）

- 一级上下文：关注/热门/7x24/自选/视频/基金/资讯/达人/私募/ETF。
- 二级上下文：关注流为全部/关注精选/只看原发/未分组，自选流为全部/公告/新闻；同一选择器覆盖后续动态标签。
- 2026-08-14 登录态取证：普通流为 `.status-list > article.timeline__item` + `a.date-and-source[data-id]`，分析字段为 `order=smart`；7x24 为 `.timeline__live tr`，日期分组标题与行内 `HH:mm` 组合解析。
- 普通流与 7x24 均先通过滚动追加，达到阈值后出现“加载更多”；当前阶段统一标记“仅过滤已加载内容”，不宣称找全区间结果。
- 每个上下文隔离缓存、加载游标、去重集合、过滤数和无法解析数；切换时取消旧异步任务并重新绑定 DOM。
- 严格区分“只过滤已加载内容”和“可跨页/滚动完整查找”；热度流不得承诺时间范围结果完整。
- 雪球首页、个股页、详情评论、截止模式和区间模式全部验收前，不启动其他平台正式适配。

### 6.3 通用滚动补拉引擎（v1.0 核心项）

```
过滤后 T 前可见帖数 < MIN_TARGET(默认20) → 触发补拉
  → 程序化滚动/点击"加载更多"
  → 终止：≥ MIN_TARGET / 翻页≥MAX_PAGES / "没有更多" / 新帖时间已越过T
```

- 防抖 + 可中断 + 页数上限防风控
- 补拉前自动切严格时间序（适配包 `sort_controls`）
- 拉不到时诚实提示："该平台可能未提供更早内容"
- 适配包标注 `history_depth` 供补拉引擎决策

### 6.4 SPA 路由监听

知乎、B站、GitHub 等 SPA 页面 URL 变化不触发页面加载 → Content Script 状态需重置。需监听 `history.pushState` / `navigation` 事件。

### 6.5 虚拟滚动元素去重

X/Twitter、YouTube 等虚拟滚动页面，滚出视口的帖被回收、滚回来重新渲染 → 计数器重复计数。需"已处理元素指纹去重"逻辑。

### 6.6 窗口模式现状

- `TimeSettings` 与内容脚本判定层已支持 `mode: 'window'`，保留区间为 `start ≤ 时间 ≤ end`。
- 雪球虚拟分页可直接复用同一判定，但只有起止边界完整时才会启动。
- Popup 已支持截止/区间模式切换、双时间输入、顺序校验、回显和通用区间预设；金融场景预设与真实 Chrome 验收仍在 v1.0 待完成。
